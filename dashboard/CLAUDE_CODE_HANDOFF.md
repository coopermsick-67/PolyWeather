# WeatherPicks — Claude Code handoff

_Last reviewed: 2026-09-03, against commit history through the security/reliability audit pass (server.py hardening, dashboard_payload.py fault isolation, BacktestWorkspace validation, CI added)._

## Product truth

WeatherPicks is an experimental daily-high weather research dashboard for
settlement-station markets. It is not betting, financial, or weather-safety
advice, and it must never claim a guaranteed edge, outcome, or profit.

## Current implementation

- React/Vite frontend in `src/`, a Flask API in the repo root (`server.py`,
  deployed per `render.yaml`), and two generated Cloudflare/browser Workers
  built by `scripts/create-worker.mjs`: `public/xgb-worker-model.json` +
  its runtime (client-side residual inference) and `public/backtest-worker.js`
  (client-side backtest scoring).
- The public backtest scores immutable archived rows (from
  `dashboard/public/backtest-data.json`, generated by
  `scripts/export_backtest_data.py`) in a browser Worker. It is static
  historical scoring, **not** an on-demand forecast replay and not a durable
  background job. `BacktestWorkspace.jsx` now rejects a start date after the
  end date client-side before ever spawning the worker.
- The residual model is historically evaluated only for `KLAX`, `KMDW`,
  `KMIA`, `KNYC`, and `KSFO` (see `artifacts/production_v2/model_manifest.json`).
  Preserve the `SHADOW_ONLY` disclosure. `dashboard_payload.py` now treats a
  missing/unreadable manifest as "no station is calibrated" rather than
  silently trusting every station — never revert that to a permissive default.
- The frontend auto-refreshes every 15 minutes (`App.jsx`) and the NWS client
  caches each upstream endpoint response for 2 minutes in-process
  (`nws.py`, LRU-bounded at 256 entries). Independently, `server.py` now
  short-caches the full assembled payload per date for 20s
  (`_PAYLOAD_CACHE_TTL_S`) so several near-simultaneous requests for the same
  date don't each re-run model inference and upstream fetches; the frontend's
  manual refresh button sends `?refresh=1` to bypass that cache on purpose —
  do not remove that param without also removing the bypass logic in
  `server.py`'s `dashboard()` route.
- Same-station NWS observations provide a current-day high floor, and a
  tested NBM/HRRR/GFS consensus is shown as uncalibrated guidance for
  stations outside the trained five.
- CI (`.github/workflows/test.yml`) runs `pytest` and `npm test` + `npm run
  build` on every push/PR to `main`. Keep new Python logic covered by
  `tests/*.py` and new pure frontend logic covered by a co-located
  `*.test.js` file (Node's built-in test runner, no framework installed —
  see `src/dateUtils.test.js` for the pattern); nothing else currently gates
  merges.
- `ALLOWED_ORIGINS`, `NWS_USER_AGENT`, and `FLASK_DEBUG` are read from the
  process environment by `server.py`/`nws.py`; see `.env.example` at the repo
  root. `ALLOWED_ORIGINS` in particular must be set in the actual Render
  service (declared with `sync: false` in `render.yaml` so Render prompts for
  it) — leaving it unset makes the API accept requests from any origin.

## High-value next improvements

1. Add a durable forecast-issuance store (timestamped inputs and outputs) so
   backtests can evaluate frozen live runs rather than an archived composite.
2. Add a provider relay or permitted server-side weather gateway; public edge
   deployment may fall back to single-source NWS when Open-Meteo rejects the
   batch request. Never label that fallback as multi-source.
3. Add browser tests for backtest `runId` acknowledgement, zero-row errors,
   rapid re-runs, and worker failures. (Client-side start/end date-order
   validation now exists in `BacktestWorkspace.jsx`, but the worker
   lifecycle itself — cancellation, error surfacing — is still untested.)
4. Add city-level calibration only after prospective validation; do not extend
   the five-city residual model by copying offsets or heuristics.
5. Audit dark-dashboard contrast and narrow-screen table behavior. (Location
   picker keyboard navigation — arrow keys, Enter, `aria-activedescendant` —
   is now implemented; that part of this item is done.)

## Guardrails

- Preserve `WeatherPicks` in all user-facing UI and metadata. The Python
  `polyweather` package is intentionally not renamed yet because it is a
  breaking internal API change.
- Keep the landing disclaimer adjacent to all pick-oriented copy.
- Do not add payment, wagering, trade execution, or outcome-guarantee flows.
- Build with `npm run build`; it regenerates `public/backtest-data.json` and
  the deploy Workers. Do not hand-edit `dist/`.
- Run `pytest` (repo root) and `npm test` (in `dashboard/`) before committing
  backend or frontend logic changes — both are fast and both now run in CI,
  so a red local run means a red PR.
- `server.py`'s `/api/dashboard` route is deliberately fault-isolating: one
  station's upstream failure or a bad `model_manifest.json` should degrade
  that station/calibration, never 500 the whole response. Preserve that
  shape in any future change to `dashboard_payload.py`'s fetch/build loop.
